O problema

A nuvem é o gargalo.

Depender de servidores para cada prompt custa caro, atrasa tudo e leva seus dados embora. Para um dispositivo de borda, isso não escala.

01

Dependência

Cada inferência paga latência, custo e vendor lock. Um sistema operacional não pode depender de alguém estar online.

02

Latência

Ida e volta na rede a cada prompt. Para automação e agentes, isso é o gargalo real — não o modelo.

03

Seus dados saem

Prompt, resposta e contexto vão para fora. Privacidade e conformidade viram o problema, não a exceção.

A solução

Um SO, redefinido para IA.

O aios roda a inferência dentro do próprio dispositivo. O modelo, o runtime e a interface vivem juntos — local, rápido e sob seu controle.

0Na nuvem

Local-first de verdade

O daemon edge-ai sobe junto com o sistema. Health, inferência e métricas respondem em milissegundos, sem sair da máquina.

Rust+ Redox

Leve, rápido, seguro

Kernel e userland enxutos, sem bloated runtime. O binário do edge-ai tem ~8 MB e roda em CPU pura — sem GPU, sem CUDA, sem nuvem.

Q4GGUF

Tiny models,greso completo

Modelos GGUF quantizados (TinyLlama, família tiny) rodam bem em hardware modesto. O registry gerencia install/remove e versões offline.

1Daemon

Uma interface para tudo

API HTTP local, CLI edge e painel web — status, inferência, benchmark, logs e métricas num lugar só.

O sistema operacional

Um desktop que trabalha com IA.

Não é uma distro com um app de inferência. É um sistema operacional onde o runtime de IA é parte da primeira classe — compilado, embarcado e acessível desde o boot.

Developer OS

Perfil ai-developer: toolchain Rust/C/Python embarcada, terminal, editor e o painel edge — tudo local.

Edge OS

Perfil ai-edge: imagem mínima que boota direto para serviço de IA — daemon ativo, sem GUI, sem ruído.

Família de tiny SLM

Pequenos o bastante para qualquer lugar.

Modelos GGUF quantizados em Q4: bem menos memória, inferência aceitável e zero chamada de rede. A família tiny é a primeira camada — e roda na Raspberry Pi.

Principal · TinyLlama

TinyLlama 1.1B

O caballo de batalha: ~668 MB em Q4_K_M, ~7 t/s no host e ~1,7 t/s dentro do guest. Cabe em Raspberry Pi e desktop alike.

Micro · Hello

Hello 1B

Modelo mínimo para smoke, benchmark e testes de pipeline. Onde a latência vira o gargalo, ele prova o caminho.

Raspberry Pi

Do seu desk ao seu edge.

O mesmo runtime, do desktop à Raspberry Pi. aarch64 é alvo de deploy: o daemon, o CLI e os modelostiny rods em hardware de borda real.

aarch64

Perfil ai-edge construído para Raspberry Pi. Inferência em CPU, sem GPU — o tiny SLM roda onde você quiser.

Portátil

Cross-build --target aarch64-unknown-redox. O mesmo código, do seu notebook ao Pi na borda da rede.

Apps próprios

O que já roda no aios.

Não é só um kernel. É um ecossistema de apps próprios que já funcionam offline, no próprio dispositivo.

Daemon

edge-ai

Serviço HTTP local: health, models, inferência, benchmark, logs, métricas e painel web num binário só.

  • bind-first (sobe já, pré-carrega o modelo em background)
  • API JSON estável
  • painel web embutido
CLI

edge & ai

edge: status, models, run, benchmark, logs, monitor, serve. ai: install, run, tasks (summarize, classify, intent…).

  • tasks com roteamento por config
  • registry e cache offline
  • JSON output
Core

ai-core & ai-inference

Parser GGUF, SHA-256, registry TSV e backend de inferência em Candle CPU — a foundation sobre a qual tudo roda.

  • streaming de metadata >1 MiB
  • benchmarks reais
  • sem dependência de nuvem
SDK

edge-sdk

Camada de geração para apps e agentes: carregue um modelo do registry e gere tokens com métricas de TPS e tempo de load.

  • generate / generate_with_metrics
  • integração com agentes
