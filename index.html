O problema

A nuvem é o gargalo.

Depender de servidores para cada prompt custa caro, atrasa tudo e leva seus dados embora. Para um dispositivo de borda, isso não escala.

01

Dependência

Cada inferência paga latência, custo e vendor lock. Um sistema operacional não pode depender de alguém estar online.

02

Latência

Ida e volta na rede a cada prompt. Para automação e agentes, isso é o gargalo real — não o modelo.

03

Seus dados saem

Prompt, resposta e contexto vão para fora. Privacidade e conformidade viram o problema, não a exceção.

A solução

Um SO, redefinido para IA.

O aios roda a inferência dentro do próprio dispositivo. O modelo, o runtime e a interface vivem juntos — local, rápido e sob seu controle.

0Na nuvem

Local-first de verdade

O daemon edge-ai sobe junto com o sistema. Health, inferência e métricas respondem em milissegundos, sem sair da máquina.

RustRuntime enxuto

Leve, rápido, seguro

Userland enxuto, sem bloated runtime. O binário do edge-ai tem ~8 MB e roda em CPU pura — sem GPU, sem CUDA, sem nuvem.

Q4GGUF

Tiny models, progresso completo

Modelos GGUF quantizados (TinyLlama, família tiny) rodam bem em hardware modesto. O registry gerencia install/remove e versões offline.

1Daemon

Uma interface para tudo

API HTTP local, CLI edge e painel web — status, inferência, benchmark, logs e métricas num lugar só.

O sistema operacional

Um desktop que trabalha com IA.

Não é uma distro com um app de inferência. É um sistema operacional onde o runtime de IA é parte da primeira classe — compilado, embarcado e acessível desde o boot.

Developer OS

Perfil ai-developer: toolchain Rust/C/Python embarcada, terminal, editor e o painel edge — tudo local.

RustCPythonIon shell

Edge OS

Perfil ai-edge: imagem mínima que boota direto para serviço de IA — daemon ativo, sem GUI, sem ruído.

headless~8 MB daemonoffline

Base de sistema: Redox OS — o aios escreve o runtime de IA, os binários e a experiência em cima dessa base.

Família de tiny SLM

Pequenos o bastante para qualquer lugar.

Modelos GGUF quantizados em Q4: bem menos memória, inferência aceitável e zero chamada de rede. A família tiny é a primeira camada — e roda na Raspberry Pi.

Principal · TinyLlama

TinyLlama 1.1B

O caballo de batalha: ~668 MB em Q4_K_M, ~7 t/s no host e ~1,7 t/s dentro do guest. Cabe na Raspberry Pi e no desktop.

Projeto oficial GGUF Q4_K_M

Apps próprios · AIOS

Apps que nascem junto com o sistema.

Desenvolvidos pela organização AIOS, abertos e em Rust/TypeScript: não é só um daemon, são apps que rodam offline e conversam com o mesmo runtime.

Em construção · MIT

Laya Gateway

App próprio

Gateway local entre o seu agente e o seu LLM: a Laya decide qual ferramenta chamar em uma pergunta pequena e tipada; o resto da requisição segue direto para o modelo. Fail-open por design — se a Laya cair, a requisição passa intacta.

  • Fail-open: nunca bloqueia o agente
  • Proxy OpenAI Chat Completions
  • Rust + Actix (API) e Next.js (painel)
github.com/aios-b-612/laya-gateway
Em construção · MIT

Web SQLite Admin

App próprio

Administração open source de bancos SQLite com frontend Next.js e API Rust/Actix. Login por senha, bases, tabelas, busca, CRUD, schema, importação, exportação, integridade e console SQL em um só lugar.

  • Console SQL e VACUUM/integrity
  • Import/export e busca por coluna
  • Sidecar local em imagem única
github.com/aios-b-612/web-sqlite-admin

Sistema · aios

O que já vem pronto no sistema.

Cada peça do aios é um crate ou um binário próprio, em Rust, compilado para o desktop e para o Pi. Nada de dependência de nuvem.

Runtime e CLIsexecutáveis do sistema
Sistema

edge-ai

Daemon HTTP local: health, models, inferência, benchmark, logs, métricas e painel web num binário só. Sobe primeiro e pré-carrega o modelo em background.

~8 MB · bin/edge-ai crate edge-ai
Sistema

edge

CLI do daemon: status, models, run, benchmark, logs, monitor e serve. É o painel de linha de comando do dispositivo.

edge status bin/edge
Sistema

ai

CLI de modelos e tarefas: list, info, inspect, verify, install, remove, doctor, run e ai task (summarize, classify, intent, translate, qa) com roteamento por config.

ai task classify crate aios-cli
Bibliotecas do núcleocrates compartilhados
Sistema

ai-core

Núcleo compartilhado: parser GGUF com streaming, SHA-256, cache global, registry TSV e metadados de modelo. O modelo é dado local — a gestão também.

GGUF · SHA-256 · registry crate aios-core
Sistema

ai-inference

Backends de inferência em Rust puro sobre Candle CPU, com streaming de tokens. A base sobre a qual o daemon, o CLI e o SDK geram texto.

Candle CPU · streaming crate aios-inference
Sistema

edge-sdk

SDK para apps e agentes de borda: carrega um modelo do registry e gera tokens com métricas de TPS e tempo de load, com a mesma API do core.

load · generate_with_metrics crate aios-sdk
